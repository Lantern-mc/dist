설치하기

Lantern 패널은 Docker Compose로 한 컨테이너에서 웹 패널과 마인크래프트 서버를 함께 실행합니다. 첫 기동 후 설정 코드로 Discord를 연결하고 관리자를 정합니다.

필요한 것

섹션 제목: “필요한 것”
  • Docker와 Compose v2 (docker compose 명령)
  • 호스트에서 8080(웹 패널)과 25565(게임)를 열 수 있는 환경. Cloudflare Tunnel·TCPShield를 쓰면 주소 공개처럼 호스트 포트 구성이 달라질 수 있습니다
  • Discord OAuth는 HTTPS와 등록된 Redirect URL이 필요합니다. http://localhost:8080은 로컬 테스트용이며, LAN IP나 HTTP만 있는 주소로는 로그인이 깨질 수 있습니다
  • 마인크래프트 서버 실행 시 Minecraft EULA에 동의해야 합니다

Compose 준비

섹션 제목: “Compose 준비”

저장소 루트의 compose.yaml을 기준으로 합니다. 배포용 이미지 예시는 docker/IMAGE_README.md의 ghcr.io/lantern-mc/lantern:latest 블록과 같고, 소스에서 빌드할 때는 같은 파일의 build: 항목을 씁니다.

이름 있는 볼륨 네 개가 데이터를 담습니다 (lantern-data, lantern-backups, lantern-client-cache, lantern-head-cache). 예전 ./lantern-data 바인드 마운트에서 옮기려면 compose.bind.yaml과 scripts/migrate-to-volumes.ps1을 데이터 위치와 업데이트·docs/ops/volumes.md 순서대로 따릅니다.

선택 파일( git에 올리지 않음):

  • cloudflared.env ← cloudflared.env.example (패널 터널)
  • tcpshield.env ← tcpshield.env.example (게임 터널)
  • offsite.env ← offsite.env.example (백업 사이드카, docker compose --profile offsite)

시스템 백업 암호화·DB 키 분리는 compose.yaml 주석의 LANTERN_SYSTEM_BACKUP_PASSPHRASE_FILE, LANTERN_SECRET_KEY_FILE 예시를 참고합니다. 기본으로는 켜지지 않습니다.

실행

섹션 제목: “실행”

compose.yaml이 있는 폴더에서:

컨테이너가 뜬 뒤 로그에서 설정 코드를 찾습니다.

로그에 Lantern 설정 코드: XXX-XXX 한 줄이 나옵니다(형식 XXX-XXX). Discord 연결 전에 코드를 잃으면 docker compose exec lantern lantern setup-code로 새 코드를 받을 수 있습니다. 설정이 끝나기 전까지 로그를 읽을 수 있는 사람은 설정을 마칠 수 있으므로, 첫 기동 직후 바로 마무리하는 것이 좋습니다.

첫 접속과 설정 마법사

섹션 제목: “첫 접속과 설정 마법사”
  1. 브라우저에서 패널 HTTPS 주소(로컬이면 http://localhost:8080)를 엽니다. 아직 설정되지 않았으면 Discord 연결(/setup)로 이동합니다.
  2. 설정 코드를 로그에서 복사해 넣습니다.
  3. Discord 개발자 포털에서 앱 만들기 → 값 붙여넣기에 애플리케이션 ID, 클라이언트 시크릿, 봇 토큰, 이 패널의 웹 주소를 넣습니다. Redirect는 …/api/auth/callback입니다.
  4. 봇을 우리 Discord 서버에 초대로 봇을 길드에 넣습니다.
  5. 연결 확인을 눌러 네 가지 검사(앱 정보, 봇 로그인, 봇이 서버에 있음, 멤버 목록)가 통과하는지 봅니다. 길드가 여러 개면 연결할 Discord 서버를 고릅니다.
  6. 이 브라우저로 Discord 로그인으로 들어온 계정이 관리자가 됩니다.

같은 화면 아래 백업에서 복원은 멤버·세션이 없을 때만 보입니다. 절차는 백업과 복원과 docs/ops/restore-runbook.md를 따릅니다.

설정이 끝나면 서버 만들기와 콘솔 시작하기 체크리스트로 이어집니다. 흐름 요약은 docs/onboarding-flows.md에 있습니다.

데이터가 있는 곳

섹션 제목: “데이터가 있는 곳”

컨테이너 안 /lantern이 lantern-data 볼륨입니다. DB·secret.key·server/(월드 포함)·업로드 파일이 여기 있습니다. 월드 백업 파일은 lantern-backups → /lantern/backups에, CurseForge 클라이언트 zip 캐시와 플레이어 머리 캐시는 각각 lantern-client-cache, lantern-head-cache에 있습니다.

docker compose down -v는 볼륨을 지우므로 쓰지 않습니다. 평소 중지는 docker compose down입니다. 표와 분류는 데이터 위치와 업데이트를 보세요.

패널 이미지 올리기

섹션 제목: “패널 이미지 올리기”
  1. docker compose pull 또는 소스를 받은 뒤 docker compose build
  2. docker compose up -d

패널과 마인크래프트 서버는 같은 컨테이너 프로세스 트리입니다. 이미지를 바꾸고 컨테이너를 다시 만들면 마인크래프트 서버도 함께 재시작됩니다.

RCON(25575)은 컨테이너 안에서만 쓰며 호스트에 노출하지 않습니다.

막혔을 때

섹션 제목: “막혔을 때”
  • 설정 코드를 확인해 주세요.: 코드 오타 또는 분당 실패 제한. 로그·lantern setup-code로 다시 확인합니다.
  • Discord 연결 후 관리자를 모두 잃었거나 봇 토큰이 폐기됐을 때: 호스트에서 docker compose exec lantern lantern recover로 복구 코드를 발급합니다.
  • 네트워크·터널: 주소 공개, 문제 해결

관련: Discord 연결, 처음 시작하기(플레이어 런처).
