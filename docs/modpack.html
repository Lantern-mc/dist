모드팩 배포

플레이어가 서버와 같은 CurseForge 클라이언트 모드팩을 쓰도록 배포 파일 화면에서 프로필 zip과 프로필 코드를 등록합니다. Windows Lantern Launcher가 코드·zip을 읽어 인스턴스를 맞춥니다.

운영자: 올리기

섹션 제목: “운영자: 올리기”
  1. CurseForge 앱에서 서버와 맞는 클라이언트 프로필을 Export as .zip file로 내보냅니다.
  2. 같은 프로필에서 Generate code → Copy Import Code로 코드를 복사합니다. zip과 코드는 같은 시점의 한 쌍이어야 합니다.
  3. 패널 배포 파일의 새 쌍 올리기에 프로필 zip과 코드를 넣고 올립니다. zip과 코드를 모두 넣으면 켜집니다.
  4. 올릴 때마다 팩 버전이 1씩 올라갑니다.

코드만 갱신: 모드팩은 그대로이고 코드만 만료됐을 때 코드만 바꾸기에 새 코드(와 선택적 코드를 만든 때)만 넣습니다. zip과 manifest_fingerprint는 그대로입니다.

프로필 코드는 생성 후 7일 동안 유효합니다. 만료 36시간 전에 운영자에게 알림이 갑니다. 만료 후 만료됨으로 표시됩니다.

화면의 CurseForge에서 만드는 방법 보기 튜토리얼에 단계별 스크린샷 설명이 있습니다.

런처 동기화

섹션 제목: “런처 동기화”

플레이어가 서버 들어가기(lantern://launch?…)를 누르면:

  1. 웹이 일회용 티켓(5분, expires_in 300초)을 만들고 런처가 토큰으로 교환합니다.
  2. 런처가 GET /api/launcher/pack으로 pack_version, zip_url, profile_code, manifest_fingerprint, mc_version, loader, mod_count, server.address 등을 받습니다.
  3. CurseForge 앱으로 인스턴스를 만들거나 갱신하고, 필요하면 zip의 overrides/를 반영합니다. manifest_fingerprint가 바뀌면 모드 구성이 달라진 것입니다.
  4. 코드가 expired이면 code는 null이고, 런처는 수동 가져오기 안내를 보여 줍니다.

모드팩 미리 받기(action=prepare)는 게임을 켜지 않고 같은 준비만 합니다. 자세한 API 필드는 docs/launcher-api.md를 참고합니다.

플레이어가 보는 화면

섹션 제목: “플레이어가 보는 화면”

랜딩 런처 카드: 서버 들어가기, 모드팩 미리 받기, 런처 받기, .zip 다운로드, 모드팩 상세 정보. 배포가 없으면 서버장이 아직 모드팩을 올리지 않았어요와 운영자용 배포 파일 올리기 링크가 나옵니다.

모드팩 받기 페이지(downloads):

  • 설치하고 실행하기 — 서버 들어가기: Windows·CurseForge 앱·런처 필요.
  • 직접 가져오기 — 프로필 코드 또는 프로필 zip (zip 받기). 코드 만료 시 zip·튜토리얼 안내.
  • 서버 주소 — 런처로 들어가면 목록에 자동 추가.

손님에게 승인 전에 미리 받아 두면 바로 들어올 수 있어요 카드는 랜딩 옵션 guest_download와 modpack.download 권한이 켜져 있을 때 보입니다. 역할별 권한은 역할과-권한에서 조정합니다.

다운로드 권한

섹션 제목: “다운로드 권한”

모드팩 zip·코드·런처 API는 modpack.download 권한이 있는 멤버만 받습니다. 기본적으로 플레이어·손님 역할에 포함되며, 관리자가 역할 편집기에서 뺄 수 있습니다.

패널 자동 zip과의 차이

섹션 제목: “패널 자동 zip과의 차이”

배포 파일 화면의 클라이언트 zip 구성(자동 생성·CurseForge 원본 등)은 웹 모드팩 받기의 jar 묶음용이며, 런처 프로필 zip·코드와는 별 트랙입니다. 런처 중심 커뮤니티는 프로필 쌍을 우선 등록합니다.
