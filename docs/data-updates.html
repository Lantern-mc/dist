데이터 위치와 업데이트

Lantern 상태는 Docker 이름 있는 볼륨에만 저장합니다. 호스트 ./data 폴더 바인드는 기본 compose.yaml에 없습니다(Windows Docker Desktop에서는 볼륨이 도커 가상 디스크 안에 있습니다).

볼륨과 컨테이너 경로

섹션 제목: “볼륨과 컨테이너 경로”
볼륨 컨테이너 경로 내용
lantern-data /lantern SQLite DB, secret.key, server/(월드·설정), 업로드·브랜딩·자동화 등
lantern-backups /lantern/backups 월드 *.tar.zst, system/ 시스템 백업
lantern-client-cache /lantern/client-cache CurseForge 클라이언트 zip 캐시(재다운로드 가능)
lantern-head-cache /lantern/cache/heads 플레이어 머리 캐시(재다운로드 가능)

볼륨 이름은 compose.yaml의 name:으로 고정되어 프로젝트 폴더 이름과 무관하게 같은 볼륨을 재사용합니다.

server/는 설치·복원·초기화 때 /lantern 최상위에서 통째로 바꿔치기하므로 별도 볼륨으로 쪼개지 않습니다. 백업 경로 /lantern/backups는 DB에 절대 경로로 저장되므로 마운트 위치를 바꾸지 않습니다.

/lantern 안에서 중요한 것

섹션 제목: “/lantern 안에서 중요한 것”

LANTERN_DATA_DIR(도커 기본 /lantern) 기준 분류는 docs/ops/data-layout.md 표와 같습니다.

반드시 따로 보관할 것

  • lantern.db — 멤버·역할·설정·백업 목록
  • secret.key (또는 LANTERN_SECRET_KEY_FILE로 마운트한 키 파일) — Discord 토큰 등 DB 암호화 키
  • server/의 월드 폴더 — 월드 백업으로
  • backups/의 .tar.zst — 패널 백업 화면과 DB 목록

시스템 백업에 들어가지만 월드·모드 jar는 제외

  • server.properties, 화이트리스트·밴 목록, kubejs/, 플러그인 설정·데이터(일부 크기 상한), branding/, direct-mods/, dist/files/ 등

지워도 다시 만들 수 있음

  • server/mods/, libraries/, 서버 jar — 같은 설치 명세로 재설치
  • client-cache/, cache/heads/, dist/build/ — 필요 시 재생성

패널 밖에 둘 비밀

섹션 제목: “패널 밖에 둘 비밀”
  • Docker secret / env 파일: LANTERN_SYSTEM_BACKUP_PASSPHRASE, LANTERN_SECRET_KEY_FILE, cloudflared.env, tcpshield.env, offsite.env — git·공개 위키에 넣지 않습니다.
  • 받아 둔 시스템 백업 파일 — 평문이면 secret.key 포함. 암호화 백업은 암호문을 백업 파일과 다른 안전한 곳에 보관합니다.
  • Discord 개발자 포털 클라이언트 시크릿·봇 토큰 — DB에는 암호화 저장되나 시스템 백업·복구 절차를 알고 있는 사람은 접근 가능합니다.

LANTERN_SECRET_KEY_FILE을 켠 뒤 다른 바이트의 키로 바꾸면 이미 DB에 저장된 비밀은 복호화되지 않습니다.

RCON

섹션 제목: “RCON”

게임 RCON 포트 25575는 server.properties의 server-ip가 비어 컨테이너의 모든 인터페이스에서 받습니다. compose.yaml은 호스트에 게시하지 않지만, 같은 Docker 네트워크의 다른 컨테이너에서는 닿을 수 있습니다. rcon.password는 시스템 백업에 ***로 가려지며, 패널이 서버를 켤 때마다 새 값을 씁니다.

패널 이미지 업데이트

섹션 제목: “패널 이미지 업데이트”
  1. 새 이미지를 받거나 빌드합니다 (docker compose pull 또는 docker compose build).
  2. docker compose up -d로 컨테이너를 다시 만듭니다.

코드·런타임은 이미지에, 위 볼륨 데이터는 그대로 유지됩니다. 패널 업데이트 시 같은 컨테이너의 마인크래프트 서버 프로세스도 재시작됩니다.

더 새 Lantern이 만든 시스템 백업은 더 오래된 이미지로는 복원이 거절됩니다. 복원 전에 패널 이미지를 먼저 올립니다.

마이그레이션은 패널 부팅 시 DB에 적용됩니다. 코드를 이전 버전으로 되돌릴 때는 docs/ops/restore-runbook.md의 alembic downgrade 안내를 먼저 따릅니다.

볼륨 유지·이전

섹션 제목: “볼륨 유지·이전”
  • 중지: docker compose down (-v 사용 금지 — 볼륨 삭제)
  • 바인드 마운트에서 이전: compose.bind.yaml + scripts/migrate-to-volumes.ps1 (docs/ops/volumes.md)
  • 볼륨 tarball 백업: docker run --rm -v lantern-data:/v:ro … — 패널이 켜진 채 DB 파일을 tar로 복사하면 깨질 수 있음. DB·키는 시스템 백업 사용
  • 새 호스트: 백업과 복원, docs/ops/restore-runbook.md

Lantern 밖에서 백업할 것

섹션 제목: “Lantern 밖에서 백업할 것”
  • 시스템 백업 아카이브(및 sha256 메모)
  • 월드 .tar.zst 파일
  • (선택) LANTERN_SECRET_KEY_FILE 실물, 시스템 백업 암호
  • Discord·Cloudflare·TCPShield 계정 설정(패널 DB 밖)
  • 백업과 복원 오프사이트 사이드카 대상의 lantern-backups-*.tar.gz

관련: 설치하기, 백업과 복원, 주소 공개.
