주소 공개

플레이어와 운영자가 쓰는 주소는 두 종류입니다. 패널(HTTPS·Discord OAuth)과 게임(TCP 25565, 선택적으로 TCPShield)을 따로 잡습니다.

패널 웹 주소

섹션 제목: “패널 웹 주소”

설정 › 주소 › 웹 접속에서 패널 주소(public_url)를 넣습니다. Discord OAuth Redirect는 이 값 기준 …/api/auth/callback입니다.

  • 인터넷에 공개할 때 8080을 그대로 노출하지 않습니다. HTTPS 역 프록시 또는 Cloudflare Tunnel을 앞에 둡니다(docker/IMAGE_README.md).
  • 주소를 바꿀 때는 Discord 개발자 포털 Redirects를 먼저 맞추고, 위 내용을 확인했습니다 체크 후 저장합니다.

로컬 테스트만 할 때는 http://localhost:8080이 동작할 수 있으나, Discord 로그인·쿠키는 HTTPS 공개 URL을 기준으로 맞추는 것이 안전합니다.

게임 접속 주소

섹션 제목: “게임 접속 주소”

설정 › 주소 › 접속 카드(게임 접속 주소)에서 주소 필드에 플레이어가 멀티플레이에 넣을 호스트(필요하면 :포트)를 적습니다. 비우면 플레이어 화면에 주소가 보이지 않습니다(비워 두면 플레이어 화면에 주소가 보이지 않습니다).

기본 마인크래프트 포트는 25565입니다. compose.yaml은 호스트 25565:25565를 게시합니다. 포트는 서버 설정에서 바꿀 수 있으며, TCPShield를 쓰면 TCPSHIELD_GAME_PORT도 같이 맞춥니다.

이 패널 주소: … 제안을 이걸로 정하기로 게임 주소 초안으로 쓸 수 있습니다. TCPShield·음성 채팅은 보통 별도 DNS 이름이 필요합니다(아래 TCPShield 절).

Cloudflare Tunnel (패널, 선택)

섹션 제목: “Cloudflare Tunnel (패널, 선택)”

패널 HTTP(컨테이너 8080)만 터널로 내보냅니다. 게임 포트는 이 터널로 가지 않습니다.

  1. Cloudflare Zero Trust에서 터널을 만들고 public hostname 서비스를 http://localhost:8080으로 지정합니다.
  2. cp cloudflared.env.example cloudflared.env 후 CLOUDFLARED_TUNNEL_TOKEN=에 토큰을 넣습니다.
  3. docker compose -f compose.yaml -f compose.cloudflared.yaml up -d

compose.cloudflared.yaml은 호스트 포트 게시를 비웁니다(ports: !reset []). TCPShield와 함께 쓸 때는 -f compose.yaml -f compose.cloudflared.yaml -f compose.tcpshield.yaml 순서로 겹칩니다. TCPShield 파일이 UDP 터널 포트를 다시 게시합니다.

100MB 업로드 제한

섹션 제목: “100MB 업로드 제한”

Cloudflare(무료·Pro)는 요청 본문 100MB를 넘기면 패널에 도달하기 전에 거절합니다. 패널 업로드 한도와는 별개입니다.

  • 90MiB를 넘는 파일은 패널이 50MiB 조각으로 나눠 올립니다(help.json 큰 파일 올리기). 터널 뒤에서도 조각 업로드는 100MB 제한을 피합니다.
  • 설정 마법사 백업에서 복원 업로드는 설정 코드만 쓰며 분할 업로드를 쓰지 않습니다. 큰 시스템 백업은 CLI 복원(docs/ops/restore-runbook.md)을 고려합니다.

TCPShield (게임, 선택)

섹션 제목: “TCPShield (게임, 선택)”

Sentry Tunnel로 게임 TCP를 TCPShield 뒤에 둡니다. 웹 패널 경로와 분리합니다.

  1. TCPShield 패널에서 Sentry Tunnel Setup Script 값을 tcpshield.env에 복사합니다(cp tcpshield.env.example tcpshield.env).
  2. 공유기·방화벽에서 UDP TCPSHIELD_PORT를 이 호스트로 포워딩합니다.
  3. docker compose -f compose.yaml -f compose.tcpshield.yaml up -d
  4. TCPShield 백엔드를 터널 공개 IP(TCPSHIELD_IP)와 게임 포트에 맞춥니다.

터널 안 iptables로 8080(패널)과 25575(RCON)는 밖에서 닿지 않게 막습니다. 게임 TCP는 TCPShield 프록시 대역(TCPSHIELD_ALLOW, 기본 198.178.119.0/24 104.234.6.0/25)에서만 받습니다.

Docker Desktop / WSL2에서는 vxlan tx checksum offload를 끄지 않으면 접속이 SYN-RECV에서 멈출 수 있습니다. docker/entrypoint.sh가 ethtool -K vxlan_<id> tx off를 실행합니다.

Simple Voice Chat UDP는 CNAME(TCP 전용) 대신 터널 IP를 가리키는 A 레코드와 LANTERN_VOICE_HOST, LANTERN_VOICE_BIND 환경 변수로 맞춥니다(docs/ops/tcpshield.md).

RCON과 내부 포트

섹션 제목: “RCON과 내부 포트”

RCON 25575는 컨테이너 내부용이며 compose.yaml에 게시하지 않습니다. 패널이 서버를 켤 때마다 rcon.password는 새로 잡습니다.

자주 겪는 증상

섹션 제목: “자주 겪는 증상”
증상 점검
Discord 로그인 실패 패널 주소·Redirect·HTTPS
게임 목록 핑만 되고 접속 실패 TCPShield 터널·체크섬 offload·백엔드 IP
<터널 IP>:25565 직접 접속 됨 TCPSHIELD_ALLOW·터널 방화벽
큰 zip 업로드 중단 Cloudflare 100MB; 조각 업로드 또는 우회(docs/wiki/networking-troubleshooting.md §4)
음성 채팅만 안 됨 voice_host·UDP A 레코드·bind_address
