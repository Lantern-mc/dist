백업과 복원

월드 백업과 시스템 백업은 목적이 다릅니다. 월드는 백업 화면의 *.tar.zst, 멤버·설정·비밀 키·서버 설정 파일(월드·모드 jar 제외)은 시스템 상태 카드의 시스템 백업입니다.

월드 백업 만들기

섹션 제목: “월드 백업 만들기”

백업 › 지금 백업으로 수동 백업을 만듭니다. 목록 종류에 수동 백업 / 자동 백업 / 변경 전 백업 등이 표시됩니다.

자동 백업

섹션 제목: “자동 백업”

자동 백업 카드:

  • 매일 백업 — 기본 06:00, 시간대 Asia/Seoul
  • 보관 개수 — 기본 7 (1~100)
  • 보관 기간(일) — 0이면 끄기. 0이 아니면 오래된 자동 백업을 일 단위로 지웁니다
  • 이전 백업과 동일하면 건너뛰기 — 월드 지문이 직전 백업과 같으면 그날 건너뜁니다
  • 고정한 백업은 지워지지 않습니다

서버가 바쁘거나 월드가 없으면 그날 자동 백업이 건너뛰어질 수 있습니다.

변경 전 백업

섹션 제목: “변경 전 백업”

복원·재설치·월드 리셋 전에 패널이 변경 전 백업(pre_change)을 만듭니다. 메모 예: 복원 전, 재설치 전, 월드 리셋 전. 고정하지 않은 pre_change는 최근 5개만 남깁니다. 서버 초기화 전에는 pre_reset_full(메모 서버 초기화 전)이며, 고정하지 않은 것은 최근 2개만 남깁니다.

고정·내려받기

섹션 제목: “고정·내려받기”
  • 고정 / 고정 해제 — 자동 삭제 안 함
  • 백업 파일(.tar.zst) 받기 — 복원용 원본. 일반 zip 프로그램으로는 열 수 없습니다
  • zip으로 내보내기 / 지금 월드를 zip으로 내보내기 — 플레이어가 읽을 수 있는 zip

검증됨은 만든 직후 파일 전체를 읽어 SHA-256을 DB에 저장했다는 뜻입니다. 검증 안 됨은 예전 백업입니다.

월드 복원

섹션 제목: “월드 복원”

복원… → 이 백업으로 복원 확인.

  1. 서버를 멈춥니다
  2. 지금 월드를 변경 전 백업으로 먼저 백업합니다(메모 복원 전)
  3. 선택한 시점의 .tar.zst로 월드 폴더를 교체합니다
  4. 필요하면 서버를 다시 켭니다

SHA-256이 저장된 백업은 복원·다운로드 전에 다시 해시해 손상을 잡습니다. 해시가 맞지 않으면 복원이 거절됩니다.

초기화 전 전체 백업 종류는 목록·다운로드만 되고 월드 복원 버튼은 없습니다.

시스템 백업

섹션 제목: “시스템 백업”

시스템 상태 카드(백업 화면 오른쪽, 관리자):

  • 지금 시스템 백업 — backups/system/system-<UTC>.tar.zst (+ .json 메타)
  • 매일 자동, 최근 7개 보관 — 기본 켜짐. 월드·mods/ jar·재생성 가능 캐시는 제외
  • 시스템 백업 받기 — 다른 디스크로 옮겨 보관

암호화되지 않은 백업에는 비밀 키와 자동화·서버 설정 파일이 평문으로 들어 있어요 경고가 표시됩니다. 컨테이너에 LANTERN_SYSTEM_BACKUP_PASSPHRASE(또는 _FILE)를 주면 .tar.zst.enc로 저장됩니다. 암호문을 잃으면 그 백업은 열 수 없습니다. 암호는 환경 변수에만 두며 DB·로그에 남기지 않습니다.

SSH 키·.pem 등은 SSH 키 같은 자격 증명 파일 N개는 빠졌어요 안내대로 백업에 없습니다. 복원 뒤 다시 만들어야 합니다.

새 호스트로 옮기기

섹션 제목: “새 호스트로 옮기기”

요약(docs/ops/restore-runbook.md):

  1. 새 호스트에 같은 Lantern 이미지와 빈 볼륨 lantern-data, lantern-backups 준비
  2. 패널을 끈 상태에서 python -m lantern.cli restore-system으로 시스템 백업 복원 (--expect-sha256 권장)
  3. 월드 .tar.zst 파일을 lantern-backups 볼륨에 원래 파일명 그대로 복사
  4. docker compose up -d 후 Discord 로그인·패널 주소 수정
  5. 서버 jar·모드는 백업에 없으므로 서버 만들기와 같은 설정으로 재설치
  6. 백업 화면에서 월드 복원

설정 마법사에서 복원

섹션 제목: “설정 마법사에서 복원”

멤버·세션이 없는 첫 /setup에서 백업에서 복원:

  1. 설정 코드 + .tar.zst / .tar.zst.enc 올려서 확인
  2. 복원하고 다시 시작 — restart: unless-stopped 필요
  3. 부팅 시 restore-system --apply-pending 적용. 결과는 확인으로 닫습니다

암호화 백업은 브라우저가 아니라 컨테이너의 LANTERN_SYSTEM_BACKUP_PASSPHRASE로만 풉니다.

오프사이트 복사 (선택)

섹션 제목: “오프사이트 복사 (선택)”

패널 화면이 아니라 docker compose --profile offsite 사이드카가 lantern-backups 볼륨을 읽기 전용으로 tar.gz 복사합니다(docs/ops/offsite.md).

  1. cp offsite.env.example offsite.env — 로컬 볼륨·S3·SFTP 중 하나
  2. docker compose --profile offsite up -d offsite
  3. docker compose --profile offsite exec offsite backup으로 시험

기본 cron 07:00 (Asia/Seoul)은 패널 일일 백업(06:00)과 시스템 백업 대기 이후여야 합니다. BACKUP_RETENTION_DAYS 기본 14일.

클라우드로 보내기 전 시스템 백업 암호화를 권장합니다.

백업 밖에 둘 것

섹션 제목: “백업 밖에 둘 것”

같은 디스크만 쓰면 디스크 장애 시 월드·시스템 백업이 함께 사라집니다. 시스템 백업 파일과 월드 .tar.zst를 받아 두고, sha256을 따로 적어 --expect-sha256에 씁니다.

관련: 데이터 위치와 업데이트, 설치하기, 감사 로그.
